# Основной способ регистрации голоса — запись трёх фраз

Участники → карточка участника → «Записать голос с микрофона». Выбор микрофона использует существующий macOS-адаптер и CoreAudio UID. Загрузка готового файла остаётся в свёрнутом разделе «Другой способ»; регистрация из чистых реплик встречи также сохранена.

Порядок: согласие → запись предложенных трёх фраз обычным голосом → завершение → прослушивание → подтверждение одного говорящего → сохранение → локальное создание профиля. Можно добавить несколько образцов. Профиль не используется для безусловного назначения имени: совпадения требуют ручного подтверждения по существующим правилам.

## Хранение и ограничения

Запись ограничена 45 секундами в адаптере и в сервере. Родительский процесс принудительно завершает зависший адаптер. До принятия образец не попадает в voice_jobs/voice_samples и не создаёт встречи. Только принятый образец копируется в очередь локальной обработки с согласием.

Временный черновик находится в `voice-drafts` рядом с SQLite, каталог доступен только владельцу. Отмена, повторная запись и закрытие карточки удаляют черновик; при закрытии вкладки запись ограничивается по времени, а завершённый черновик истекает через 10 минут после подготовки. Незавершённые черновики предыдущего сервера удаляются при следующем запуске под эксклюзивной блокировкой. Черновики не следует включать в долговременные резервные копии. Сохранённые голосовые образцы и профили удаляются существующей кнопкой удаления биометрических данных.

Встреча и регистрация используют общий файловый замок микрофона в каталоге audio. Он действует для процессов, работающих с этой базой; другие приложения macOS он не контролирует. Обработка голосового профиля не запускается параллельно с записью образца. Смена микрофона, тест устройства, импорт и запуск распознавания блокируются на время записи образца. Готовый черновик можно прослушивать, не занимая микрофон.

Техническая проверка: mono PCM16 WAV 16 кГц, длительность 6–60 секунд, уровень, доля звучащего сигнала и перегрузка. Она не доказывает, что говорит один человек, и не проверяет дословное чтение фраз. Это подтверждается человеком после прослушивания. Модель эмбеддингов и существующие пороги сопоставления не изменены.

## Контракт

- POST voice/capture/start: person_id, device_uid, consent.
- POST voice/capture/stop или cancel: draft_id, person_id.
- GET voice/capture/audio/{draft_id}: временный WAV с Range и no-store.
- POST voice/capture/accept: draft_id, person_id, consent, single_speaker.
- GET status содержит voice_capture.draft: состояние, таймер, уровень, источник и техническую оценку. Эмбеддинги не возвращаются.

Доступны starting, recording, stopping, preparing, ready, rejected, failed. Неверный участник или идентификатор черновика отклоняется. Повторное принятие того же завершённого черновика в процессе сервера возвращает прежний job_id и не дублирует образец. После перезапуска старый идентификатор не принимается.

## Проверки

73 Rust-теста прошли, Clippy с `-D warnings` прошёл. Добавлены проверки согласия и подтверждения, предварительного прослушивания, идемпотентного принятия, отмены, владения участником, отказа для тишины, отключённого устройства без подмены источника, очистки после перезапуска, истечения черновика и взаимного исключения с записью встречи. Существующие 11 тестов записи также прошли.

В браузере на изолированной SQLite и искусственных микрофоне/эмбеддингах пройден полный путь до одного зарегистрированного профиля. Плеер загрузил WAV длительностью 8 с без ошибки. Проверены отказ без согласия, отказ без подтверждения после прослушивания и отмена по Escape. Встречи при этом не созданы; после сохранения и отмены временных черновиков нет.

Реальный микрофон автоматически не включался. Аппаратная приёмка требует явного запуска пользователем; тестовые эмбеддинги не измеряют качество узнавания человека.
