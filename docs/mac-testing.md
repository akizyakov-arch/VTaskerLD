# MacBook Air M5 / 16 ГБ

Для обновления существующей установки и проверки нового сценария используйте [пошаговое руководство панели](web-panel.md).

## Первая установка

Распакуйте исходники в каталог `VTaskerLD`. Установите Xcode Command Line Tools (`xcode-select --install`), Rust через https://rustup.rs/ и откройте новый Terminal. При установленном Homebrew: `brew install cmake ffmpeg python git`. Нужен Python с `tarfile.data_filter` (рекомендуется 3.12+).

Из каталога исходников:

```sh
bash scripts/setup-macos.sh --with-microphone
bash scripts/start-macos.sh --db "$HOME/Library/Application Support/VTracker/data.sqlite3"
```

Модели скачиваются с проверкой контрольных сумм, инструменты находятся в `$HOME/.local/share/vtracker`. БД и аудио по указанному пути остаются вне OneDrive. Сохраните тот же `--db` при будущих обновлениях.

Для первого прогона: tiny, один worker, до четырёх потоков, VAD выключен. Это экономичная начальная конфигурация, не измеренный профиль производительности M5. После проверки работоспособности можно оценивать более точную модель.

## Без моделей

```sh
bash scripts/setup-macos.sh --recording-only
bash scripts/start-macos.sh --db "$HOME/Library/Application Support/VTracker/data.sqlite3"
```

Этот путь требует Rust, Swift и C++ toolchain, но не загружает STT/диаризацию. Интерфейс разрешает запись и честно сообщает, что распознавание недоступно. WAV можно импортировать без FFmpeg; для M4A/MP3 нужен FFmpeg.

## Разрешения и закрытие

Первый старт микрофона запрашивает системное разрешение. Если доступ запрещён, проверьте разрешение Terminal/адаптера в настройках конфиденциальности macOS. Уровень и пауза требуют нового адаптера: пересоберите его через setup с `--with-microphone`. Для старого адаптера пауза отключена, чтобы команда не завершила запись неожиданно.

Закрытие вкладки не завершает запись. Перед остановкой сервера завершите запись в панели и дождитесь сохранения. Для восстановления после аварии откройте карточку и подтвердите остановку прежнего процесса. Сохранённые WAV не удаляются ошибкой модели.

**Фактически проверено в облаке:** Linux-ядро, Chromium, синтетическая запись, реальные FFmpeg и публичные ML-примеры из отдельных отчётов. **Не проверено здесь:** сборка нового Swift-кода на Mac, микрофон, разрешения macOS, Safari, VoiceOver, Metal и длительная запись на M5. Готового подписанного `.app` нет.


## Проверка выбора устройства (2 ноября 2026)

Сборки Rust и Swift выполнены на Mac arm64. CoreAudio обнаружил встроенный микрофон MacBook Air и Continuity-микрофон iPhone. Двухсекундная CLI-проверка встроенного устройства прошла, возвращён реальный уровень. Исправлена ложная остановка по уведомлению AVAudioEngineConfigurationChange при неизменном работающем устройстве: проверка состояния выполняется в основном цикле, остановленный поток, отключение и смена формата остаются ошибкой.

36 Rust-тестов и clippy пройдены; новые сценарии проверяют передачу выбранного UID, метаданные в БД/экспорте и восстановлении, отказ без fallback при недоступном устройстве, проверку уровня без аудиофайлов/встреч. Проверка облачного адаптера: 5 тестов.

Требуют ручной приёмки: iPhone/USB/Bluetooth, отключение физического устройства, смена системного микрофона во время сессии, запись 2 часа. Фактическое качество распознавания базовой речи пользователь принял; WER/DER на согласованном наборе не измерены.
