# Проекты: цель, этап и препятствия

В форме создания и редактирования проекта добавлены:

- `goal`: цель проекта, до 4000 символов;
- `next_milestone`: ближайший этап, до 500 символов;
- `next_milestone_date`: необязательная календарная дата этапа;
- `blocker`: препятствия, до 4000 символов.

Цель, этап, его срок и препятствия видны в карточке списка и в обзоре проекта. Поиск находит проекты по названию, описанию, цели, этапу и препятствиям. Обзор также показывает реально заблокированные текущие задачи со ссылками на их карточки. Внутри проекта есть действия «Изменить проект» и «Задача».

Поля хранятся в существующем `projects.data_json`; схема SQLite остаётся версии 14. Новая миграция не требуется. Старые проекты открываются с честными пустыми состояниями. Сохранение из старого клиента без новых полей сохраняет их предыдущие значения. Пустые строки или null позволяют явно очистить поля. Если дата этапа указана, название этапа обязательно. История проекта сохраняется существующим механизмом change_events, изменения защищены revision. Задачи и зависимые сроки автоматически не меняются.

Проверки: 65 Rust-тестов прошли, Clippy с `-D warnings` прошёл. Три новых теста проверяют сохранение после повторного открытия БД, совместимость со старым клиентом, валидацию типов/лимитов/дат с откатом, очистку полей и отказ устаревшей версии. В браузере на отдельной SQLite проверены сохранение, reload, поиск по этапу и мобильный список без горизонтальной прокрутки (390 CSS px). В тестовой сессии ошибок консоли нет. Пользовательские проекты для проверки не создавались.

Перед началом итерации сделана полная локальная копия проекта с Git-историей, согласованной SQLite, аудио, голосовыми файлами, моделями и инструментами, без пересоздаваемых кэшей сборки. Копия размещена вне папки облачной синхронизации; личные файлы резервной копии в репозиторий не включаются.
