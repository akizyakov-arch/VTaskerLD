# План развития VTASK и Валли

Рабочая база — `v0.1.0-rc.1`. Ветка рекомендаций аналитика — `feature/analyst-roadmap`. Параллельная разработка ведётся в `feature/meeting-changes`.

## 1. Версия 0.2.0 · Изменения после встречи

- Сопоставлять поручения с существующими задачами по проекту и контексту встречи. При нескольких подходящих вариантах предлагать выбор.
- В «На подтверждение» показывать новые задачи, изменения сроков, исполнителей и статусов, решения и блокировки. Для изменений показывать текущее и предложенное значения и фрагмент протокола.
- При повторном анализе сохранять ручные правки и подтверждённые изменения, добавлять только новые предложения. Значимые изменения применять после проверки человеком.
- После проверки отдельных предложений добавить пакетное согласование и подготовку повестки по открытым вопросам предыдущих встреч.

**Приёмка.** Проверить на совещании с несколькими проектами однозначное совпадение, выбор между одноимёнными задачами, историю изменений и повторный анализ без дублей.

## 2. Версия 0.3.0 · Валли для команды

- Подключить один мессенджер через VPS-шлюз. Связать аккаунты с участниками и проверять права в локальном ядре.
- Дать сотрудникам доступ к их задачам, приём поручений и возможность сообщать статус или блокировку.
- Настроить очередь доставки при выключенном Mac и защиту от повторной обработки. Добавить рабочие часы, напоминания и уведомления о блокировках.

**Приёмка.** Сообщение принимается при выключенном Mac и обрабатывается один раз после подключения. Сотрудник получает только доступные ему сведения.

## 3. Версия 0.4.0 · Память проектов

- Добавить поиск по словарю, документам, протоколам и подтверждённым решениям.
- Показывать первоисточник каждого ответа о договорённостях и учитывать права доступа.
- Использовать найденные сведения в сводках и повестках.

**Приёмка.** Валли отвечает, почему принято решение, и открывает исходную запись или документ.

## 4. Дальнейшее развитие · Координация

- Выявлять риски по срокам, блокировкам и зависимостям. Готовить сводку для руководителя и предложения по перепланированию.
- Определить правила для групповых чатов и согласовать модель синхронизации нескольких клиентов после пилота.

## Порядок работы

Начинаем с трёх сценариев версии 0.2.0: одно совпадение, несколько совпадений и повторный анализ. Ведём статус выпусков в [журнале версий](CHANGELOG.md). Базовая работа с проектами и задачами опирается на локальное ядро Rust и SQLite. Порядок этапов задаёт приоритеты, даты выпуска определяем после приёмки.
